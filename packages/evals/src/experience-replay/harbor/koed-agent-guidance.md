# Koed Memory

Your user installed Koed to give you access through `memory_answer` to their Personal Memory and, when configured and authorized, relevant Team Memory. Before beginning substantive work in a new chat, and whenever an existing chat moves to a sufficiently new topic, consult Koed before committing to a plan or implementation. Ask whether the relevant available Personal or Team scope contains prior experience, decisions, constraints, preferences, facts, successful approaches, failed attempts, or validation results that could affect the work.

Ask a focused first question. If an answer identifies useful knowledge but lacks a necessary detail, ask a narrower follow-up. Existing-project implementation, debugging, validation, configuration, design, and decision-making work normally warrant recall. Skip recall only when the task is simple and you are certain that memory cannot materially help.

Select `delivery_mode` from the next planned action. Use `blocking` when memory supplies the answer, can change an immediate decision or edit, or when independence is uncertain. Use `non_blocking` when useful independent diagnostics can run first, even if the eventual fix depends on prior memory. Follow explicit User instructions to wait or continue independent work. Omitted and `auto` preserve the calling integration's configured default and do not classify the query; configuration opt-outs and unsupported contexts remain authoritative.

After a pending receipt, do only useful independent work, then yield at Codex's native Stop boundary before a memory-dependent decision. The hook awaits completion outside the model loop and supplies the result to the original turn. Do not poll, use sleep tools or artificial work to postpone that boundary, repeat the recall in blocking mode, invent prior constraints, or claim dependent work is complete. Apply the recalled result before the dependent action. If delivery fails or acceptance is uncertain, report the unavailable prerequisite and leave dependent work unresolved without resubmitting. Stop after a successful not-found result.
