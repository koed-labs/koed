Assessed on 2026-10-15 against `f35815b4a8cad5bcb96782dbb02e35d8c43bf488`, with three Luna Extra High reviews. The assessment below records the starting point. The implementation checkpoint at the end supersedes its gap descriptions; live release acceptance remains separate.

## Agreed behavior

Reuse resources already configured in the actual execution AI Client, on the selected computer and in the authorized Project. A model name does not identify the resource source. Changing models inside one Client must retain that Client's source; switching Client, computer or Project must invalidate incompatible selections.

Settings should group discovered resources by Client and computer. Typing `/` in an Agent chat should offer that execution Client's usable Skills. Automatic native Skill use should remain supported where the Client permits it. Koed must not copy every Skill into each prompt, create another extension registry, or implement provider marketplaces. Installation, account connection and settings management stay in the original Client. Existing Koed GitHub PR authorization remains independent.

Preserve Koed's execution permissions, owner/device/Project authorization and the existing Memory path. In particular, Ticket 04's instruction-only Claude path must keep `settingSources: []`; enabling native Project settings wholesale would reverse the User's explicit permission-isolation decision. The recalled suggestion to enable Project settings predates that decision and is not current implementation authority.

## Implementation checkpoint

The shared catalog now separates native availability (`available`, `configured`, `needs_sign_in`, `disabled`, `unavailable`, `unknown`) from Koed execution support (`koed_managed`, `inventory_only`, `unknown`). Legacy status remains conservative. Only a Skill with explicit available/managed evidence and native invocation can be selected. Codex discovery reads the pinned protocol's enabled/callable/runtime fields rather than treating every installed resource as usable. Production plugin-management methods remain excluded.

Studio and the retained Electron Personal composers reuse the same `@koed/ui` picker. Each adapter validates the actual Client, computer and Project. First messages and continuation carry opaque IDs through the existing managed execution route. A model change within the same Client retains choices; a Client/computer/Project change clears them, including A → B → A navigation. Choices expire at the earliest retained catalog deadline. Owner-private hosted launch supports the picker before execution controls are shown. Shared human/request composers do not expose another owner's library. PR review's separate read-only execution remains outside this picker contract.

Electron discovery reuses the authenticated resource-operation endpoints through a strict main/preload IPC route. The renderer supplies only a registered Client ID and Project ID; it cannot provide provider paths or an API destination. Selection payloads contain bounded opaque IDs and target scope. A recovered rejected first message requires Skill reselection because the transient catalog/expiry is not persisted; recovery retains its opaque diagnostic scope and explains this requirement. Accepted or uncertain first messages are reconciled without replay.

Settings inventory uses no Project; Project Skills are read in the corresponding Agent chat. Refresh rechecks the target once and performs one catalog discovery, with a bounded deadline, cancellation, limited retry and readable sign-in/offline errors. Expired catalogs are hidden until refreshed. Installation and external account connections remain in the original Client. Koed's GitHub authorization is unchanged.

Discovery operations now recheck the enabled Client and current device grant on replay, read, claim, heartbeat, completion and failure. A revoked, expired or narrowed grant cannot return a catalog or settle an in-flight result. Lease revision/token checks prevent an older runner from publishing after replacement. Disposable PostgreSQL tests cover these cases without migrating the configured Personal database.

### Claude isolated native bridge

The supported bridge is verified against `@anthropic-ai/claude-agent-sdk` 0.3.226 and native CLI 2.1.226. Discovery uses passive plugin metadata and an isolated metadata-only native query, with no model turn. Its zero-message input stays open until metadata control requests finish and is released on success, failure or abort, so EOF cannot close the query prematurely. It does not use `reloadPlugins` with user/Project settings. Custom registered config directories and authorized Project `.claude` roots retain their actual native namespaces. Only verified definitions are selectable; ambiguous names and unsupported executable versions remain unavailable for managed invocation. Installed plugins may have a canonical installation directory outside the Client config root: that directory must be returned by the exact configured Client’s native plugin inventory again during send-time revalidation. It is never supplied by the browser. Raw user/Project roots remain bound to the registered config directory and authorized Project.

One explicit Claude Skill is supported per turn. The native slash command receives the existing User prompt as its arguments; Koed does not paste Skill bodies into the public prompt or create an extra Memory/extension registry; the existing raw provider capture remains authoritative. The provider's Skill filter is not treated as a sandbox. The private adapter validates canonical native roots and bounded definitions, rejects executable frontmatter and shell interpolation, scans each root once within a shared 4 MiB definition budget, excludes extra commands/agents, disables hooks/plugin MCP discovery, and keeps Koed's explicit MCP configuration. Every isolated turn, including continuation without a new Skill, retains an ask-all permission rule and disabled hooks. The original approval callback still decides tool access. A selected Skill cannot enable another settings source. Claude subagent execution through a selected Skill is unavailable.

The persisted native fixture also confirms that Claude emits expanded Skill instructions as `isMeta: true` user records. The existing parser classifies these as provider-internal activity, so they do not become a human message or advance the human turn. Canonical raw source evidence remains in the existing capture flow.

The pinned native fixture uses a disposable HOME/config root and a fake Anthropic HTTP endpoint, without provider credentials or external model calls. It verifies actual slash invocation, custom-root names, refusal of ambiguous/unsafe definitions and tool denial under default, acceptEdits, auto, bypassPermissions and dontAsk modes. This is executable integration evidence, not live account acceptance. Native extensions that require wider settings, hooks, additional agents or plugin MCP are inventory-only. Original Client installation/sign-in and the default-off Ticket 04 instruction snapshot gate remain unchanged.
