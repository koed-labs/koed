# Team Collaboration Action And Credential Matrix

This document is the authoritative action-level credential and authorization
matrix for Team collaboration. It covers implemented HTTP routes, Electron IPC
commands and events, local-edge channels, and realtime operations.

The matrix describes admission to an operation, not durable authorization.
Every accepted operation still resolves current Team Membership, role,
Workspace Access, Share Grant, representation, lifecycle, retention,
entitlement, encryption, and resource scope before selecting, decrypting,
mutating, or publishing protected data.

## Credential Boundaries

| Code   | Principal or boundary        | Permitted custody and use                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| ------ | ---------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BS`   | Browser session              | An HTTP-only, human-authenticated remote User session. It may directly perform authorized Team operations. Fresh reauthentication is required where stated. It is never sent to Electron renderer code.                                                                                                                                                                                                                                                         |
| `PAT`  | Personal API Token           | A Personal Memory compatibility credential for an AI Client. It never authorizes collaboration UI, Team, Shared Memory, Share Grant, administration, or collaboration realtime operations.                                                                                                                                                                                                                                                                      |
| `LEC`  | Local-Edge Client Credential | A per-install credential accepted only by the authenticated OS-local `koed-server` boundary, bound to one enrolled backend and explicit operation families. It is not accepted by the remote Team backend and is never sent to the renderer.                                                                                                                                                                                                                    |
| `UDC`  | Upstream device credential   | A remote credential owned and used only by local `koed-server`, bound to one remote User, device, backend, credential version, and operation-family allowlist. The `action_grant` family permits only browser-confirmed grant mediation and exact grant-bound execution; it is not reusable `admin` authority. The credential never contains current Team authorization and is never returned to Electron main, preload, renderer, MCP Server, or Capture Hook. |
| `RT`   | Electron renderer trust      | Successful sender-origin validation plus an allowlisted, schema-valid preload command from the current renderer frame. It is not an HTTP credential and grants no remote authority by itself.                                                                                                                                                                                                                                                                   |
| `AG`   | Action grant                 | A short-lived, one-action, one-request, one-device, one-backend, and where applicable one-Team authorization produced from fresh browser confirmation. It is additional authority, not a reusable credential.                                                                                                                                                                                                                                                   |
| `ANON` | Unauthenticated bootstrap    | Allowed only for the explicitly named enrollment challenge bootstrap/status operations. It grants no Team data access.                                                                                                                                                                                                                                                                                                                                          |

`LEC` and `UDC` may use the same HTTP authentication scheme in the current
implementation, but they are different credentials with different verifiers,
custody, audience, and authority. A renderer cannot substitute `RT` for `BS`,
`LEC`, or `UDC`, and no credential acquires authority because it can reach a
route.

## Fail-Closed Rules

Every matrix row names one of these behaviors.

| Code        | Required fail-closed behavior                                                                                                                                                                                                                                                                                                                                                            |
| ----------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `FC-P`      | Require the current local Personal owner for the exact thread or source. Reject missing identity with `401`, wrong owner/scope with `403`, and return no remote fallback or cross-User data.                                                                                                                                                                                             |
| `FC-TR`     | Require a valid `BS` or correctly scoped `UDC`, then re-evaluate enabled Team Membership and the exact Team/thread/Workspace/participant or Share Grant predicates before selection and decrypt. Reject `PAT`, wrong operation family, path substitution, stale lifecycle, and inaccessible resources with `403` and no protected DTO.                                                   |
| `FC-TW`     | Apply `FC-TR` plus current write authority, input bounds, idempotency, optimistic version, rate limits, and transactional outbox. Reject stale version or idempotency conflict with `409`; encryption or outbox failure aborts the write.                                                                                                                                                |
| `FC-SA`     | Require the Personal source owner, exact enrolled identity link, exact preview/consent/policy binding, current Workspace share authority, and an explicit representation intersection. Reject drift, fallback fidelity, wrong owner, missing policy, or invalid authority before materialization or disclosure.                                                                          |
| `FC-ADM`    | Require current server-side role/capability checks and either fresh `BS` or a valid scoped `UDC` plus exact one-use `AG` where stated. Reject absent, expired, replayed, wrong-device, wrong-backend, wrong-Team, wrong-action, or request-hash-mismatched grants with `403`; reject stale versions with `409`.                                                                          |
| `FC-SYNC`   | Require the exact source/target deployment, User, credential lineage, relationship, logical Memory, cursor, package, and encryption bindings. Reject `PAT`, wrong profile, wrong side, stale/revoked relationship, checksum drift, or unavailable encryption without accepting plaintext or advancing cursors.                                                                           |
| `FC-LE`     | Require OS-local trust, valid backend-bound `LEC`, enabled route policy, fresh compatible capabilities, exact operation family, narrow method/path allowlist, and an available stored `UDC`. Return `401`/`403` for trust or credential failure and `424` for unavailable/stale upstream state; never downgrade Team work to local Personal authority.                                   |
| `FC-RT`     | Bind snapshot, stream, replay, and acknowledgement to backend, principal, device, client instance, subscription, Team, protocol version, and opaque cursor. Reauthorize snapshot, each replay batch, and live serialization; force a content-free close on revocation, expired history, backpressure, deadline, or protocol mismatch without advancing the durable cursor.               |
| `FC-IPC`    | Accept only a trusted renderer origin and an allowlisted schema-valid command. Reject extra fields, reusable credentials, arbitrary URLs except the validated connection URL field, arbitrary HTTP proxy inputs, stale responses, and mismatched result/event discriminants. Clear protected renderer state on revocation, disconnect, identity/backend change, and broker invalidation. |
| `FC-ENR`    | Expose only bounded public challenge state before authentication. Bind approval, redemption, and rotation to the exact challenge, User, backend, device instance, requested operation families, expiry, and credential lineage; issue no credential on mismatch or replay.                                                                                                               |
| `FC-COMPAT` | Preserve the same request-time Team, Workspace, owner, lifecycle, and credential checks as the canonical operation while a restricted compatibility route remains callable. It grants no broader DTO, cursor, or mutation authority and is not used by the collaboration renderer.                                                                                                       |

### Shared Memory

`workspace.memory.share_owned` is independent from generic Workspace write
access. It is required for new previews, Pending Shares, and fidelity changes.
Withdrawing it prevents new sharing work. It does not prevent the source owner
from revoking an existing grant.

## Electron IPC Commands

All IPC commands are admitted only by `RT`. `BS`, `PAT`, `LEC`, and `UDC` are
denied as renderer-provided fields for every row. Electron main and preload must
not accept a credential-bearing configuration object or arbitrary HTTP request.
Opaque invitation text and bounded action-grant references are the only
operation-specific authority artifacts allowed by the shared command schema;
neither is a reusable remote credential.

### Personal Memory IPC

The fixed `koed:personal-memory:command` channel exposes
`personal.notes.list`, `personal.notes.load`, `personal.notes.create`,
`personal.notes.rename`, and `personal.notes.update`. Each operation accepts
only a trusted renderer sender and its exact schema. Electron main owns the
Personal API Token, maps each request to one fixed route and method, and never
accepts a renderer-supplied URL, header, credential, owner, Memory Event id, or
source revision.

### Collaboration IPC

The generic `team_read`, `team_chat`, `team_chat_subscribe`, and
`team_chat_unsubscribe` commands are not accepted. Backend connection remains a
separate bounded Desktop operation; collaboration data and mutations use only
the strict command channel below.

## Electron IPC Events

Events flow only from Electron main/preload to an `RT` renderer. The renderer
cannot publish these event channels, and no event may contain `BS`, `PAT`,
`LEC`, `UDC`, remote URLs, upstream subscription IDs, or upstream cursors.

### Typed Events

The shared schema defines the following event discriminants. Main and preload
use the dedicated `koed:collaboration:event` channel and validate the schema
before sending or mutating renderer state.

## Verification Contract

The automated authorization suites must exercise each row with its positive
credential and with denied credential substitution, resource-path
substitution, stale lifecycle, revoked authority, and malformed input where
applicable. Electron tests additionally prove sender-origin checks, exact-schema
admission, result correlation, event validation, and protected-state clearing.
Realtime tests cover snapshot acknowledgement, replay, duplicate delivery,
revocation, backpressure, reconnect exhaustion, and fresh-snapshot recovery.
