# Static AppImage ASAR extraction: blocked

`scripts/linux-appimage-extractor.mjs` exports `extractAppImageAsar({ imagePath, image, expectedSha256, maxAsarBytes })`. **It currently never returns ASAR bytes. Do not use it as a release gate.** It fails closed even for valid archives: selected-path `unsquashfs` extraction does not prove that SquashFS directories have unique names or that the ASAR is not hardlinked. An experimental standalone validator exists but is not integrated or independently reviewed; duplicate and hardlink safety are not established for production.

The caller supplies an independently verified lowercase SHA-256 digest and a trusted, locally provisioned Docker image containing `/bin/sh`, `unsquashfs`, `wc` and `cat`; image-reference validation is syntactic, not a trust or provenance check. The helper copies candidate bytes into a private snapshot, checks its digest, and inspects and mounts that snapshot. The caller must protect the snapshot directory from other processes running as the same user, and Docker daemon and supplied image are trusted. Docker never pulls an image. Container and snapshot cleanup failures are reported; a failed Docker cleanup may require manual removal of the named `koed-extract-*` container.

The experimental extraction runs as non-root, with no network, dropped capabilities, no privilege escalation, read-only root and candidate, bounded memory, processes, temporary storage, output and time. Missing, symlink, FIFO and oversized fixtures are rejected. Hardlinks and even regular fixtures are rejected at the unresolved uniqueness check, rather than accepted as safe.

## Experimental raw SquashFS helper

`scripts/linux-squashfs-helper.c` accepts a standalone raw SquashFS file and an output-byte limit, not an AppImage or offset. It walks directory entries with libsquashfs, rejects unsorted or duplicate names and repeated inode numbers, and reads the selected inode with the same library. It caps input at 4 GiB, entries and inode numbers at 100,000, depth at 64 and output at 128 MiB. It uses the lower-level metadata reader to compare encoded directory-entry numbers and types with loaded inodes, rejects repeated inode numbers and physical references, and bounds inode-table references. These checks do not prove hardlink safety or agreement with other SquashFS consumers. With libsquashfs 1.2.0, `sqfs_meta_reader_read_inode` adds the inode-table start internally despite its header describing an absolute block position; other library versions require verification. Never run it directly on hostile input: output, entry and input limits do not bound libsquashfs metadata allocation or CPU work. It requires external isolation, a trusted immutable input, CPU and wall-clock timeouts, memory, process and output limits; it is not connected to the existing extractor.

For experimental tests, use an Ubuntu 24.04 linux/amd64 image with `gcc`, `libc6-dev`, `libsquashfs-dev` and `squashfs-tools`, and run `KOED_SQUASHFS_DEV_IMAGE=<local-image> node --test scripts/linux-squashfs-helper.test.mjs`. Tests compile the helper and use synthetic raw filesystems; they include modified duplicate-name, mismatched-type, forged-number, invalid-reference and repeated-reference entries. Parser containers run as non-root with read-only input and root, no network or capabilities, bounded resources and forced cleanup. A container crash, timeout or Docker error is not counted as a rejection. The image is not pinned for production, and the suite skips unless explicitly enabled. Independent security review of the new metadata traversal and table bounds, malformed-directory termination, forged link counts, distinct references with duplicate inode numbers, additional root aliases, cycles and metadata-exhaustion tests, compression variants, differential testing against the intended runtime, mandatory CI, safe bounded AppImage offset handling, trusted image provisioning and real release testing remain necessary before considering integration. The production fail-closed gate must remain in place.

## Fixture findings

On an aarch64 Docker host, an Ubuntu 24.04 image with `squashfs-tools` 4.6.1 built for `linux/amd64` exercised synthetic fixtures under emulation. `unsquashfs` extracted a hardlinked ASAR successfully when selecting only that path, demonstrating that checking the resulting file alone does not establish archive hardlink safety. A FIFO exposed a shell `set -e` pitfall in an earlier implementation: an `&&` test list allowed execution to continue and block on FIFO input. Explicit conditional rejection fixed it. Detached containers are waited on with a timeout and force-removed afterward, because killing an attached Docker client did not reliably close inherited output pipes. Docker's `local` logging driver requires compression disabled when `max-file=1`.

For local regression tests, build an Ubuntu 24.04 image with `squashfs-tools` installed for `linux/amd64`, then set `KOED_SQUASHFS_TEST_IMAGE` to its local tag when running `node --test scripts/linux-appimage-extractor.test.mjs`. Without that variable, Docker integration cases skip. This fixture image is not production-pinned. No real release AppImage, native Linux runner, or release workflow has been verified by this change.
