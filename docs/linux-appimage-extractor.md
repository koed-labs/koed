# Static AppImage ASAR extraction

`scripts/linux-appimage-extractor.mjs` exports `extractAppImageAsar({ imagePath, image, maxAsarBytes })`. It returns only the bytes of `resources/app.asar`, or throws. It is not wired into release verification. The caller must provide a trusted, locally provisioned Docker image containing `/bin/sh`, `unsquashfs`, `wc` and `cat`; the helper never pulls an image. Image-reference validation is syntactic, not a trust or provenance check. Production workflow integration must select and verify its own image.

The candidate is parsed for its x64 AppImage filesystem offset, then mounted read-only. A non-root, networkless container with dropped capabilities, no privilege escalation, read-only root, bounded memory, processes, temporary storage, output and time extracts the fixed path. Missing, symbolic-link, special and oversized ASARs fail closed. The default and maximum ASAR limit is 128 MiB. Container cleanup is attempted even on failure; if Docker becomes unavailable, an Operator may need to remove a `koed-extract-*` container manually. The caller must prevent concurrent candidate modification and bind the inspected bytes to its own verification; a read-only container mount does not prevent host writes. Docker daemon and supplied extractor image are trusted.

## Fixture findings

On an aarch64 Docker host, an Ubuntu 24.04 image with `squashfs-tools` 4.6.1 built for `linux/amd64` extracted synthetic fixtures under emulation. Regular bytes survived; missing, symlink, FIFO and oversized fixtures were rejected. A FIFO exposed a shell `set -e` pitfall in an initial implementation: an `&&` test list allowed execution to continue and block on FIFO input. Explicit conditional rejection fixed it. Detached containers are waited on with a timeout and force-removed afterward, because killing an attached Docker client did not reliably close inherited output pipes. Docker's `local` logging driver requires compression disabled when `max-file=1`.

For local regression tests, build an Ubuntu 24.04 image with `squashfs-tools` installed for `linux/amd64`, then set `KOED_SQUASHFS_TEST_IMAGE` to its local tag when running `node --test scripts/linux-appimage-extractor.test.mjs`. Without that variable, Docker integration cases skip. This fixture image is not a production-pinned extractor image, and no actual release AppImage or release workflow has been verified by this change.
