# Studio managed Project Move

Status: implementation in progress under Ticket 04. The authority, runner, and Studio request/status/cancel paths are wired. The visible Move control is available for idle local Codex Conversations, and real standalone-to-Project, Project-to-Project, drag/drop, and dirty user-owned source transitions have passed. A dirty Koed-managed temporary worktree deletion and hosted two-device review remain open.

A Project Move changes the working context of future turns for one Koed-managed Personal AI Conversation. It preserves the execution computer, provider thread identity, and prior messages. Supported directions in this ticket are a standalone Conversation into a Project and one Project into another. Uncommitted edits stay in the source checkout, and Studio warns the user before the Move. The runner must keep that checkout accessible after success.

The owner API accepts an idempotent Move request for a destination Project ID and the execution generation/state version. It reports a Pending, claimed, cancelled, completed, or failed result. A Pending Move may be cancelled before runner claim; the claim and cancellation race in the authority database, and the persisted winner is returned. Project grouping changes only after completion. New prompts and ordinary claims are gated while a Move is active so they cannot use a stale Project context.

Owner routes are `POST /v1/managed-conversations/:executionId/project-moves`, `GET /v1/managed-conversations/:executionId/project-moves/latest`, `GET /v1/managed-conversations/:executionId/project-moves/:moveId`, and `POST /v1/managed-conversations/:executionId/project-moves/:moveId/cancel`. The latest lookup lets Studio recover Pending state after reload. Runner routes claim, renew, complete, or fail a Move with device authentication and a claim token. Only the assigned device can claim it.

The hosted authority stores only IDs, assignment, lease/fencing data, and state. The assigned runner resolves the destination path locally, records source and destination checkout details in a private local recovery journal, verifies the provider can continue the same history in the new working directory, then asks the authority to complete. Completion updates execution Project and captured-session Project attribution in one authority transaction. The browser response omits claim tokens, local paths, checkout identities, and credentials. A rejected or failed Move must preserve or recover the original working context.

Registered local Projects have opaque `lp_` IDs. Some older Captured Sessions instead use an absolute cwd as their Project ID. Move requests require opaque source and destination IDs so a local edge does not send a path-derived destination to hosted authority and the new Move record does not duplicate a local folder path. A legacy path-derived Project needs registration or opaque-ID migration before Move is available. This does not retroactively change older captured data.

The local authority and assigned runner resolve destination IDs against registered Projects metadata, including Projects with no captured Conversations. Hosted Studio currently gets destination choices from the graph Project projection, which can omit those empty Projects. Desktop uses its existing same-origin Studio gateway for Move status and cancellation.

For a source checkout with changed or unverified edits, the runner records a durable local retained-workspace locator before retiring its recovery journal. It never deletes that retained folder automatically. Local Studio lists the locator beside the moved chat and can open the folder; hosted Studio does not receive its path. A live dirty user-owned Git source retained its untracked file only in the old Project and continued in the destination Project. Studio never deletes a user-owned Project folder. A separate confirmed Delete action applies only to a verified Koed-managed temporary worktree, using the private checkout identity and managed-root confinement; legacy records without that identity are not deletable. A disposable dirty managed worktree inserted into the retained catalog was deleted through the live Studio confirmation; its catalog entry disappeared and the user-owned source file remained. Creating a dirty managed retention record from a real Move remains open. A failed Move leaves the Conversation in its original working context.

Additional AI Clients require their own live continuation validation before Move is offered.

An independent Ticket 04 review found two authority/worker edge cases. Recovery from an already committed local binding now restores and verifies the source before terminally failing when destination registration is missing; otherwise it defers and retains its journal. A failure response must be persisted as `failed` before the journal is retired. Move binding transition and completion also require a valid lease according to the database clock at mutation time. Focused worker and isolated PostgreSQL regressions passed. Local Studio now keeps Pending Move notice intent in localStorage so closing its tab does not lose the user's choice. These fixes were built into the refreshed source runtime and Studio-only review app; they do not substitute for a hosted two-device run.
