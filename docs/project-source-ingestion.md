# Project Source ingestion (HQ-209)

Document upload starts in Desktop's native file picker. The main process opens the selected file once, reads at most 25 MiB plus one byte, binds the request to the current Personal Project owner profile, and sends the bytes to the local API. The server accepts canonical base64 bytes, never a client-supplied filesystem path. Folder, repository, and skill Sources remain references.

The API saves each original binary as an encrypted owner-scoped payload referenced by a durable `project_source_revisions` attempt. A stable idempotency key returns the same attempt; a later upload with the same name and a different key creates the next revision. The API worker claims attempts with a lease generation. Extraction runs in a terminable worker thread with a 30-second limit. It accepts UTF-8 Markdown and plain text, PDF text layers, and DOCX raw text. Empty or image-only PDFs fail with `no_text_layer`; unsupported files, oversized files or extracted text, malformed files, and non-text C0 controls fail with their typed reason. Tab, CR, and LF remain valid text. OCR and backend LLM parsing are outside this path.

The extracted text is written to an actual owner Personal Note revision under the Project and Source lock in the same transaction that binds the Source attempt. The existing Note projection creates one Personal Memory Event per revision and invalidates older projected revisions. The Source becomes ready only after that exact Note revision is available in Personal Memory. A reclaim repeats the idempotent projection, including the embedding enqueue, when a crash occurs after marking the event available. The owner read route checks the active Project, Source, exact Note revision, and Note lifecycle before decrypting the text. Public Personal Note writes remain limited to 32 KiB; only the server-proven source-backed read can carry the bounded 25 MiB text.

Owner Notes listing decrypts titles only, so large Source bodies do not enter metadata pages. Source Notes use the existing authorized Personal Note recall path. The existing Team candidate-preview serialization limit is 256 KiB and remains in force; this ticket does not widen Team sharing payloads. The first-class Project-scoped retrieval selector and union belong to HQ-714. Source projection keeps the existing Personal Note metadata and materialization behavior.

Source-backed Note events use the existing heuristic token counter with its recorded `heuristic` provenance. The API verifies the owner, attempt, Note revision, revision number, and actual body hash before selecting that counter. This bounds synchronous counting for every valid document, including long unbroken text; ordinary Notes and other Memory Events retain exact tokenization. On Node 24, a 1.139 MiB normal-text sample took 389 ms with the exact tokenizer; a 32 KiB unbroken sample ran for more than 10 seconds before the diagnostic was stopped. The integration test proves the complete 32 KiB source text is retained and projected with heuristic provenance. It does not claim a full 25 MiB end-to-end stress result.

Source trash and Project delete keep Share Grant retention separate from Note forgetting. A source removal batch reserves the Source, snapshots its Note logical roots and historical backends, and uses the existing Native review and admission/freeze protocol. It marks the Source trashed only after durable sealed backend acknowledgments. A pending extraction or uncertain freeze blocks local trash. Forgetting an exact owner Note revision invalidates that revision's Personal Memory and derived recall and erases its encrypted Note body and original; older revisions remain governed by their own retention state. It does not automatically revoke already published Team grants. Explicit new upload creates a new Note when the former current revision was forgotten. Existing owner-erasure cleanup removes these new encrypted payloads. Hard Project purging has no existing service in this codebase; Project trash and restoration retain their established lifecycle.

Restrictive admission accepts the deterministic Personal Note logical root with exact owner, deployment, enrolled-device, and retained Note binding. It may establish a never-shared Note root solely to hold and seal admission; it creates no candidate preview or Share Grant. The same retained root permits freeze/cancel after a local Note revision is forgotten, so forgetting cannot strand an already published Team grant. Existing candidate publication and its size limits remain unchanged.

When a freeze requires Native review, Desktop fetches the current owner-scoped reservation and its exact Action Grant ID. The existing enrolled-device collaboration broker reads that stored grant, the main process displays the server review in an OS dialog, and the broker sends the user's decision using its existing `share_grant_management` authority. The main process checks the profile and reservation version again before sending the decision. Ordinary Project write credentials, renderer decisions, and a different device cannot confirm this grant. A canceled review leaves already frozen grants closed while the durable removal coordinator releases remaining holds.

Parser dependencies are pinned in the worker package: [PDF.js 6.4.299](https://mozilla.github.io/pdf.js/api/draft/module-pdfjsLib.html) (Apache-2.0) and [Mammoth 1.13.0](https://github.com/mwilliamson/mammoth.js/blob/master/README.md) (BSD-2-Clause). PDF.js receives in-memory data with evaluation disabled. Mammoth receives only an in-memory buffer, extracts raw text without HTML, and its installed `extractRawText` path leaves external file access disabled. The DOCX ZIP preflight checks entry count, compressed bounds, actual inflated bytes, and a 100 MiB expansion cap.
