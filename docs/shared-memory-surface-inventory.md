# Shared Memory Surface Inventory

## Inventory Version

**Shared Memory surface inventory v3 (2026-08-13).** This version describes
the implemented external and internal surfaces. A record's `version`,
`grantVersion`, policy version, source revision, or realtime protocol version is
not an inventory version.

The authorization authority is the remote Team backend. A Personal API Token
has no Team-shared Memory authority. Unless a row below narrows the rule, every
read and realtime materialization must re-evaluate the authenticated browser
session or enrolled device's `team_workspace_read` operation family, enabled
Team Membership, active Team, current Workspace Access, active Share Grant,
source-owner consent, the source-owner/Team/Workspace representation-allowlist
intersection, and the current representation and content policies before a Team
decryption key is resolved. Team and Workspace path IDs, Share Grant ID,
logical Memory ID, representation, classifier generation, and effective
content-policy hash must all bind to that same authorization decision. Missing,
mismatched, revoked, archived, suspended, invalidated, unknown-schema,
placeholder, incomplete-provenance, unsanitized, or unauthorized state is
unavailable. The fidelity ceiling is cumulative, but a missing derived layer is
not replaced with finer Personal or Team source.

## Representation Contract

- `memory_events` is the maximum-fidelity ceiling that authorizes independently
  sanitized Memory Events plus complete sanitized leaves and rollups derived
  from the same source frontier.
- `lcm_leaves` authorizes complete, current sanitized LCM Summary leaves plus
  complete sanitized rollups whose provenance exactly covers the authorized
  source revision. Their validated Team-safe lexical anchors are part of each
  encrypted materialized item and its revision hashes.
- `lcm_rollups` authorizes only complete, current sanitized LCM Summary rollups whose child
  and source provenance exactly covers the authorized source revision; the same
  lexical-anchor materialization and authorization rule applies.
- Missing, partial, LCM Placeholder, unknown-schema, forged-eligibility,
  cross-session, policy-invalidated, and safety-stale material is unavailable.
  Ordinary sync interruption may preserve the last authorized revision with an
  explicit stale state. Safety or authority invalidation removes protected
  content until a compliant representation is materialized.
- Conversation Source Access and Curated Memory are separate consent and grant
  surfaces, not additional levels in this cumulative hierarchy.
- Each Team layer is classified independently under the pinned classifier and
  versioned eight-label content policy, including titles, summaries, lexical
  anchors, nested evidence, and embedding input. Deterministic secret detection
  is unioned with model spans. Filtering is best-effort exposure reduction, not
  an anonymization or complete secret-detection guarantee.
