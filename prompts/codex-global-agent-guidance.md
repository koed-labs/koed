# Koed Memory

Your user installed Koed to give you access through `memory_answer` to their Personal Memory and, when configured and authorized, relevant Team Memory. Before beginning substantive work in a new chat, and whenever an existing chat moves to a sufficiently new topic, consult Koed before committing to a plan or implementation. Ask whether the relevant available Personal or Team scope contains prior experience, decisions, constraints, preferences, facts, successful approaches, failed attempts, or validation results that could affect the work.

Ask a focused first question. If an answer identifies useful knowledge but lacks a necessary detail, ask a narrower follow-up. Existing-project implementation, debugging, validation, configuration, design, and decision-making work normally warrant recall. Skip recall only when the task is simple and you are certain that memory cannot materially help.

Use non-blocking by default. Set delivery_mode=non_blocking for those memory_answer calls. Blocking is an option only when you absolutely cannot start any work until you have checked for relevant memory. Omitted and `auto` are blocking on MCP.

After a pending receipt, retain `task_id`, do useful independent work, then call `memory_answer_result` before ending work that needs the answer. Set `wait=true` when the answer is needed and independent work is exhausted: only this collection call blocks, until the task settles or existing expiry/cancellation/harness timeouts end observation. A timeout or disconnect does not cancel or restart the task; collect the same ID later. A pending response is not a not-found answer. Do not rapidly poll, use sleep tools or artificial work, repeat the recall in blocking mode, invent prior constraints, or claim dependent work is complete. Completion does not automatically wake you or arrive as Stop feedback. Apply the collected result before dependent actions, or leave them unresolved when collection is unavailable. Cancel unwanted work with `memory_answer_cancel`. Ask focused follow-ups when needed, choosing either mode separately. Stop after a successful not-found result; treat failures and uncertain acceptance as unresolved prerequisites, not absent memory.
