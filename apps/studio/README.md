# Koed Studio Preview

This app integrates the Personal Home and managed chat flows, the GitHub-backed
Pull Requests flow, and selected screens from the separate Studio UI prototype.
The existing Koed Desktop remains a separate app.
The original design prototype remains outside this repository.

## Run locally

Use Node 24 and the repository's pinned pnpm version.
Start your existing Koed backend before you open Studio.
Do not create a new backend configuration against an existing database without its original secrets.

From the repository root, run:

```sh
pnpm install --frozen-lockfile
pnpm --filter @koed/studio build
pnpm --filter @koed/studio start
```

Open `http://127.0.0.1:43110` for the browser preview.
Open `http://127.0.0.1:43110/?demo=1` for the labelled synthetic workflow demo.
Demo clicks, messages and decisions stay in memory and never change real Koed data.
Open `/personal-preview` and `/collaboration` for the labelled browser-local
Personal and Team previews, and
`/memory-inbox?demo=1` for a labelled Memory Inbox preview. These routes do not
create Team data or ingest memories in the backend. `/settings` uses local
appearance preferences. The exact screen-by-screen port disposition is recorded
in [the prototype port ledger](../../docs/studio-prototype-port-ledger.md).
The gateway reads the existing local credential from `~/.koed/config/local-app-credential.json`.
Set `KOED_HOME` if your existing installation uses a different directory.
Set `STUDIO_API_URL` and `STUDIO_API_TOKEN` in the server environment to select another supported local backend.
Never use a `NEXT_PUBLIC_` variable for a credential.

The browser gateway also reads the local Koed Project metadata and bounded
Codex, Claude Code and Pi conversation catalog directly from this computer.
Those local catalogs remain available when the Koed backend is stopped. A
catalog entry is a local source summary, not a Koed-managed execution: this
standalone browser preview cannot launch or control a local AI Client. Backend
Home data and local-source discovery report their availability independently.

For the Electron preview, run:

```sh
pnpm --filter @koed/studio desktop
```

Electron uses a separate configuration directory named `Koed Studio Preview`.
It opens the same Home UI through its own loopback server.
Closing Studio leaves the Koed backend running.

## Scope and validation

Home uses explicit workflow destinations; unavailable workflows remain disabled.
Home and sidebar Chats do not open captured-memory drawers.
Imported screens use live services only where the route explicitly supports
them. A preview interaction is not a substitute for a backend write or an
authorization check.
Personalised project-change briefings are planned, not generated by this preview.

## GitHub connection preview

Open Plugins in live mode to connect using the active GitHub CLI sign-in for
`github.com`. Connect is explicit; opening Studio does not read that credential.
The local service uses the token transiently to validate the account, outside the
renderer, and retains only identity status afterward. Disconnect forgets Studio's connection but does not run
`gh auth logout`. Restarting the service also disconnects Studio.

The Pull Requests slice adds repository selection, paginated PR browsing and
read-only PR summaries. Repository access is checked by GitHub on each request;
a connected account does not guarantee access to every repository. The service
looks up a transient CLI credential and verifies the connected identity before
reads. If the CLI account changes, reconnect rather than mixing account data.
Demo mode uses synthetic repositories and PRs without contacting GitHub.
The hosted GitHub App flow remains a separate implementation.

Open `/pull-requests` after connecting, or `/pull-requests?demo=1` for the demo.
All shows loaded PRs in the selected repository. Reviewing shows direct review
requests for the connected account; team-review requests are not expanded yet.
Authored matches the connected account. Search and tabs filter loaded results,
so load more pages when needed. Automated review execution, code-diff UI and publication
remain unavailable in this slice. CI, comments and review history are follow-ups;
the GitHub link opens the source PR for those details.

## PR discussion preview

Connect GitHub in Plugins, choose Browse pull requests, select a repository and
PR, then open Chat. Suggestions populate the composer; only Send starts a turn.
Reconnect revalidates the current GitHub CLI identity. Disconnect forgets the
Studio connection, not the GitHub CLI sign-in. No token is entered in the UI.

The local AI Client receives the PR description and bounded changed-file patches.
This is a discussion, not a completed audit, and cannot publish a review or comment.
Koed Memory retrieval is not connected to this first discussion slice. Missing
context must be stated rather than inferred. Large PRs may exceed patch limits.
Conversations are scoped to the GitHub account, repository, PR and reviewed
commits. A changed commit starts a new context; old replies must not be treated
as analysis of the new code. This preview keeps discussion history in the local
service's memory; restarting the service clears it.

Demo navigation keeps `?demo=1` across Home, Plugins and Pull Requests. Its
connection and repositories are synthetic. Choose **Use real GitHub** in either
demo page to leave demo mode, then explicitly connect through the live Plugins
page. No real GitHub connection is made by simulating a demo connection.

The preview reuses the repository's Codex app-server adapter and its local sign-in.
Build `@koed/mcp-server` before using live Chat. This local browser gateway is not
the hosted multi-user implementation, and standalone Electron packaging of these
new dependencies requires a later packaging pass.

The local connection commands use same-origin request checks and an expiring
CSRF token. This protects the loopback preview against cross-origin browser
requests; it is not a hosted multi-user authentication design or protection from
other processes already running as the local user.
